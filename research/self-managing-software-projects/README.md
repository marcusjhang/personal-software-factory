# Self-managing software research package

## Start here

1. Read [`report.md`](./report.md) for the evidence and recommendation.
2. Adapt [`workflow-blueprint.md`](./workflow-blueprint.md) into your project controls.
3. Start with [`templates/ticket.md`](./templates/ticket.md) and enforce the READY transition before coding.
4. Use [`templates/exception.md`](./templates/exception.md) for bounded overrides.
5. Use [`templates/postmortem-eval.md`](./templates/postmortem-eval.md) to turn failures into governed evaluation cases.

## Evidence

- `results/*.json`: 14 validated research tracks.
- `validation.txt`: final 14/14 schema validation output.
- `evidence-index.md`: 488 source records / 387 unique URLs.
- `synthesis-audit.md`: independent challenge and conflict audit.
- `outline.yaml`, `fields.yaml`: reproducible research plan and schema.

These are reference templates, not a ready-made authorization policy. Adapt risk tiers, protected paths, approvals, tests, and deployment controls to each repository.
